# JAM string canonicalization

*[Leer en español](README.es.md)*

Development and validation of an alternative duplicate-detection method
for structures generated by JAM 2.0.

## Context

JAM generates all possible stacking combinations for an n-layer system.
Many of them are equivalent under the problem's symmetries: column
rotation, column swap, layer-order inversion, sign change. The current
program detects equivalences by pairwise comparison.

The proposed method replaces that comparison with a dictionary of
canonical keys. The key of a structure is computed by applying all
operations of the symmetry group and taking the lexicographic minimum.
Two equivalent structures produce the same key.

## Formulation

    G ≅ S_3 × Z/2Z × Z/2Z     (buckled options, 24 elements)
    G ≅ S_3 × Z/2Z            (planar options, 12 elements)

    κ(a) = argmin_{x ∈ Orb(a)} σ(x)

σ encodes an array as a JAM string. Orb(a) is the orbit of a under G.

Full document in `Sobre_la_canonicalizacion_de_cadenas_JAM.pdf`:
definition of the structure set, construction of the group, definition
of κ, proof that κ distinguishes equivalence classes, pseudocode,
complexity O(|S|² · k) → O(|S| · |G| · k).

## Scripts

### Main

**`prueba_grupo.py`**
Implements the three core functions:

- `generar_grupo_std(optionx)`: builds the group operations.
- `canonical_key_std(a, optionx)`: computes the canonical key.
- `disc_equivalents_canonical_std(stackinglist, optionx)`: detects
  duplicates via dictionary.

Also defines `rot`, `transp`, `flip`, `sign`, `elementos_S3`.

**`validacion.py`**
Compares `disc_equivalents` (current method) against
`disc_equivalents_canonical_std` for all 8 options, n = 2, 3.
Verifies equal number of structures and equivalence of classes via
canonical key sets.

**`debug_validacion.py`**
Detailed diagnostic for option 4, n=2.

**`experimento_flip_sign.py`**
Compares 5 candidate groups against the current method:

- S3 (6 operations)
- S3 × flip (12)
- S3 × sign (12)
- S3 × flip × sign (24)
- S3 × (flip·sign) (12)

### Historical

**`diagnostico.py`**
First case of discrepancy (option 3).

**`experimento_sign_v2.py`**
Analysis by pairs (top_element, bottom_element) per layer.

**`experimento_sign.py`**
Initial version of the analysis by sets. Result discarded because it

## Symmetries per option

Rule: the sign change is a valid symmetry if and only if in each layer
the top and bottom elements are the same.

| Option | Type | Row | Top | Bottom | sign | Group |
|--------|------|-----|-----|--------|------|-------|
| 1 | Planar | `+0 +j +j` | j | — | n/a | S3 × flip |
| 2 | Planar binary | `+0 +j +k` | j,k | — | n/a | S3 × flip |
| 3 | Buckled | `+0 +j -j` | j | j | yes | S3 × flip × sign |
| 4 | Buckled binary | `+0 +j -k` | j | k | no | S3 × flip |
| 5 | Buckled 1H | `+0 *j (+k-k)` | k | k | yes (null) | S3 × flip |
| 6 | Buckled 1T | `*j +k -k` | k | k | yes | S3 × flip × sign |
| 7 | Ternary 1H | `+0 *j (+k-l)` | k | l | no | S3 × flip |
| 8 | Ternary 1T | `*j +k -l` | k | l | no | S3 × flip |

Option 5: sign is valid but null, because `(+k-k)` is invariant under
sign.

## Findings

### Discrepancy

Agreement between methods for options 1, 2, 5. Discrepancy for
3, 4, 6, 7, 8.

### Cause

The current method applies sign only after flip, never alone. The
resulting equivalence relation is not transitive: if flip and sign·flip
are symmetries, then sign = flip · (sign·flip) should also be one. The
code does not verify that chain.

### Evidence

Option 4, n=2:

    Candidates generated:        144
    Structures returned (old):    16
    Structures returned (new):    16
    Unique keys in old:           11
    Unique keys in new:           16

The current method returns 16 structures, of which only 11 are distinct
classes. The other 5 are undetected duplicates.

### Scope

The bug does not manifest in options 1, 2, 5 (the most used: graphene,
h-BN, MoS₂). It manifests in options with specific buckling and
ternary options.
