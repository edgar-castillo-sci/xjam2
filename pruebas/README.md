# JAM string canonicalization

*[Leer en español](README.es.md)*

Development and validation of an alternative duplicate-detection method
for structures generated by JAM 2.0.

## Context

JAM generates all stacking combinations for an n-layer system. Many are
equivalent under the problem's symmetries: column rotation, column swap,
layer-order inversion, global reflection. The current program detects
equivalences by pairwise comparison.

The proposed method replaces that comparison with a dictionary of
canonical keys. The key of a structure is computed by applying all
operations of the symmetry group and taking the lexicographic minimum.
Two equivalent structures produce the same key.

## Formulation

    κ(a) = argmin_{x ∈ Orb(a)} σ(x)

σ encodes an array as a JAM string. Orb(a) is the orbit of a under G.

The symmetry group:

    Planar options (1, 2):     G = S3 × {e, flip}              (12)
    Buckled options (3-8):     G = S3 × {e, sign·flip}         (12)

The vertical symmetry is the composition **sign·flip** (global
reflection of the system). Neither sign nor flip is used independently.

Full document in `Sobre_la_canonicalizacion_de_cadenas_JAM.pdf`:
definition of the structure set, construction of the group, definition
of κ, proof that κ distinguishes equivalence classes, pseudocode,
complexity O(|S|² · k) → O(|S| · |G| · k).

## Scripts

### Main

**`prueba_grupo.py`**
Implements the three core functions:

- `generar_grupo_std(optionx)`: builds the group operations.
- `canonical_key_std(a, optionx)`: computes the canonical key.
- `disc_equivalents_canonical_std(stackinglist, optionx)`: detects
  duplicates via dictionary.

Also defines `rot`, `transp`, `flip`, `sign`, `elementos_S3`.

**`validacion.py`**
Compares `disc_equivalents` (current method) against
`disc_equivalents_canonical_std` for all 8 options, n = 2, 3.
Verifies equal number of structures and equivalence of classes via
canonical key sets.

**`reporte_completo.py`**
Generates `reporte_completo_salida.txt` with all canonical keys
produced by each method, side by side, for all 8 options and n = 2, 3.
Marks matches at the string level.

**`benchmark.py`**
Measures filtering time (duplicate detection) for both methods.
Generates `benchmark_salida.txt` with the results.

**`correr_todo.py`**
Runs the main scripts in order and reports the final status.

### Legacy

See `legacy/README.md`. Exploratory scripts that led to the final

## Symmetries per option

Rule: the vertical symmetry is the composition sign·flip. For planar
options, sign does not apply (no vertical displacements), so the
symmetry is flip.

| Option | Type | Row | Group |
|--------|------|-----|-------|
| 1 | Planar | `+0 +j +j` | S3 × {e, flip} |
| 2 | Planar binary | `+0 +j +k` | S3 × {e, flip} |
| 3 | Buckled | `+0 +j -j` | S3 × {e, sign·flip} |
| 4 | Buckled binary | `+0 +j -k` | S3 × {e, sign·flip} |
| 5 | Buckled 1H | `+0 *j (+k-k)` | S3 × {e, sign·flip} |
| 6 | Buckled 1T | `*j +k -k` | S3 × {e, sign·flip} |
| 7 | Ternary 1H | `+0 *j (+k-l)` | S3 × {e, sign·flip} |
| 8 | Ternary 1T | `*j +k -l` | S3 × {e, sign·flip} |

In all cases the group has 12 elements.

Note on buckled options: the operation sign·flip acts as a single
transformation, not as two independent operations. For planar options,
sign is a no-op and sign·flip ≡ flip.

## Validation

Both methods (pairwise and canonical) produce **exactly the same
equivalence classes** for all 8 options and n = 2, 3. The verification
compares canonical key sets, not just counts.

Full report in `reporte_completo_salida.txt`, generated by
`reporte_completo.py`.

### Estimated old-method time at unmeasured levels

The old method is O(m²). From the last measured level, its time at
higher levels can be estimated:

| Option | n | Candidates | New (s) | Old estimated |
|--------|---|------------|---------|---------------|
| 1 | 12 | 89,304 | 18.824 | ~44,850 s (12.5 h) |
| 5 | 9 | 1,684,800 | 475.549 | ~24,760,000 s (287 days) |
| 7 | 7 | 5,985,792 | 1,628.460 | ~310,000,000 s (10 years) |

The estimate is computed as:

    t_old(n) ≈ t_old(n₀) × (candidates(n) / candidates(n₀))²

where n₀ is the last measured level of the old method.

### Empirical complexity

The canonical method scales linearly with the number of candidates:

| Option | Δ candidates | Δ time | Ratio |
|--------|--------------|--------|-------|
| 1 (11→12) | ×2.98 | ×3.04 | 1.02 |
| 5 (8→9) | ×5.99 | ×6.40 | 1.07 |
| 7 (6→7) | ×12.03 | ×13.34 | 1.11 |

The time/candidates ratio stays close to 1. This empirically confirms
O(m).

### For small n

For n = 2, 3, the old method is faster, because the canonical method
has a fixed cost per structure (applying 12 operations and converting
to string). The crossover point is between n=2 and n=3. For n ≥ 4,
the canonical method wins consistently, and the gain grows with n.
